# @oldbulb/samsara-lifecycle

`ctx.lifecycle`: every transition of a challenger row and of a round. The runner's commands, the workbench tools and the UI are consumers; none of them writes `status`, `verdict`, `compares`, `rounds`, `servings` or `noise_floors` themselves. The service asserts each step's invariant (architecture.md § Lifecycle) and refuses with a `LifecycleError` otherwise. Attempts run through the executor the runner mounts on `ctx.executor`; the service never runs a loop.

## Layout

| module | export | what |
|---|---|---|
| `@oldbulb/samsara-lifecycle` | `Lifecycle` (default export, cordis Service on `ctx.lifecycle`, inject `['ledger', 'scopes', 'gate', 'loops', 'champion']`), `LifecycleError` | the service |
| `@oldbulb/samsara-lifecycle/executor` | `Executor`, `RunRequest`, `RunDeps`, `RunResult`, `RouteConfig` | the attempt executor contract (structural; the runner's `runSet` implements it) |
| `@oldbulb/samsara-lifecycle/comparable` | `comparable`, `policySha`, `gateRefOf`, `roundPolicy` | rule 0 and the gate reference a round pins, pure |
| `@oldbulb/samsara-lifecycle/actions` | `nextActionsOf`, `NextAction` | what a consumer can do next with a row, pure |
| `@oldbulb/samsara-lifecycle` (`campaign.ts`, `controls.ts`) | `campaign`, `control` on the service; `campaignHistory`, `writeHistory`, `skillChallengerOf` | the campaign driver and the controls, over the six transitions |

`ctx.executor` is read when `run` or `calibrate` is called, not injected: the runner row mounts after this one.

## Rounds

- `preregister(input)` — an experiment row before any spend (hypothesis, prediction, pack, gate, budget). Deduplicated by content.
- `openRound({ pack, champion, metric, nEffFloor, gate?, shadowGates?, experimentId?, operator?, proposerRoute?, ... })` — refuses first, before anything is written, when `proposerRoute` (the route the proposer's adapter declares, or `'unknown'` when it declares none) is the `operator`'s normalized (provider, model) — `OPERATOR_IS_PROPOSER`: the same model cannot propose and operate a round (`sameRoute` is exported; `'unknown'` cannot be compared and is not refused here — the workbench refuses a model proposer that declares no model before it gets this far). Then proposes the champion row for these coordinates under the round's pack and metric (its `eval_config_sha` is the round's), pins the gate as `{name, version, policy_sha}` with `policy_sha = sha256(canonicalJson(policy))`, the latest noise floor for (eval config, champion, loop, metric) when one exists, and the shadow gates. The promotion gate is the policy mounted on `ctx.gate`, which must be `gate-default` or a policy a `gate_change` consent names (`GATE_NOT_CONSENTED` otherwise); a round may pin another mounted policy on the same terms. Under an experiment the gate must be the pre-registered one (`GATE_MISMATCH`) and the round budget binds (`BUDGET_EXCEEDED`). Deduplicated by `roundId`; the pack directory and the policy are kept in-process, so a resuming process calls `openRound` again with the same coordinates before touching the round's rows.
- `closeRound(id)` — decided without a promotion; scopes disposed.
- `abortRound(id)` — a round nothing drives any more (a restart, a dead host): every `running` sibling is judged `invalid` under `aborted:restart`, scopes disposed, the round closed with outcome `{ superseded: [], aborted: true }`. Refused on a decided round (`ROUND_CLOSED`) and on one with no running sibling (`BAD_TRANSITION`). What `/samsara reconcile` calls.
- `setExperimentBudget(id, budget, by?)` — the one writer of an experiment's budget: refused on a closed experiment (`ROUND_CLOSED`) and below what it already spent (`BUDGET_EXCEEDED`); the change lands on `budget_changes` with `by` (`session_id`, `command_id`) and `at`.

## The six transitions

1. `propose(proposal, { roundId })` — the proposal's parent must be the round's champion (`NOT_IN_ROUND`) and its coordinates may differ from the champion's only where rule 0 allows: `parent_ids`, `patch_sha`, `skill_sha` on the skill surface, `optimizer_config_sha`; anything else is `NOT_COMPARABLE` naming the coordinate (`detail.coordinate`), and nothing lands. The row joins `round.sibling_ids` (`k` follows). Holm's `k` is the sibling count at the first judgement (S4): once a compare row was recorded under the round no new sibling joins (`ROUND_CLOSED`; re-proposing a sibling is still idempotent). A row is a sibling of one open round at a time (`BAD_TRANSITION` for a second). Returns `{ id, created }`.
2. `open(id)` — `scopes.open` with the row's patch (the skill snapshot at `patch.skill_ref`, or the loader rows in `patch.cordis`), the pack's surface boundaries, every task id, the paths the pack's manifest protects (`protectedPaths(def)`, what the scan forbids) and an `isolate` on `ledger`, `gate`, `signoff`, `champion` and `lifecycle` (`ISOLATED_SERVICES`: nothing under the scope's fiber resolves a fixed point or its writers); a diff-scan rejection is a decided row (`invalid` by `diffscan`) and the `ScopeError` is rethrown with its violations. The champion state sha before and after must be equal (E1, `PROFILE_CHANGED`). Writes `challengers.opened {harness_sha, env_sha, profile_sha, at}` and status `opened`. The scope stays open for `run`.
3. `run(id, tier, opts)` — the champion's attempts on the tier's tasks are ensured (reused from the ledger when its latest attempt exists for every (task, sample) the run pairs on, run through the executor otherwise; `withChampion` forces a run), status goes `running` with `tier_reached`, then the challenger runs in its scope. The run id is unique per call (`run-<ms timestamp>-<process-local counter>` unless `opts.runId` is given) and names the row (`<runId>-challenger-<id[:12]>`, `<runId>-champion-<id[:12]>`), so two runs started in the same second never share an attempt id (the ledger refuses an id under another challenger anyway). A pack that declares `holdout.budget` is debited one reveal per challenger run on the held-out set — a rerun of a revealed row (more replicates, a resumed run) is no reveal — and the reveals the ledger already holds for the pack (every challenger with holdout attempts) are counted when the pack loads, so the budget survives a restart (`BUDGET_EXCEEDED` once spent); an experiment's attempt / usd / holdout-reveal budgets bind the same way and what was spent is recorded from the attempts the ledger holds under the run's ids — whether or not the executor came back, so an aborted run's attempts count — with the reveal counted once, when the row's first held-out attempt lands. Invariant: every attempt's `facts_sha` equals the champion's for the same loop, else the row is judged `invalid` on `coordinates:facts` (`summary.invalid`) and no statistic follows.
4. `judge(id, tier)` — a row `run` or the diff scan left `invalid` is refused until it runs again (`BAD_TRANSITION`); rule 0 on the rows again (`invalid:coordinates:<name>`, thrown as `NOT_COMPARABLE`), and the run invariant again on the attempts as they are now (`invalid:coordinates:facts`; the facts also reach the gate as `factsSha`, so its own rule 0 stays live); at holdout the round's noise floor is required (`invalid:noise_floor`, thrown as `NO_NOISE_FLOOR`); the judging policy is the round's gate, which must be mounted (`GATE_MISMATCH`). The compare row carries `round_id`, `replicates`, `min_effect`, `sd_source` (`noise_floor` or `comparison`) and `holm.m = k` at the most conservative rank; shadows are judged and recorded with `shadow: true`; a holdout row under a pack budget carries `holdout_budget_remaining`. First verdict wins for the coordinates and the replicates (the ledger's compare slot): a judgement over more replicates — the escalation an underpowered hold asked for — is its own row and the row's verdict; the row's verdict comes only from the promotion gate and names the round. A holdout mean that beat the Ladder moves `round.best_so_far`.
5. `decide(roundId)` — the champion served must still be the state the round opened on (`round.profile_sha`, else `PROFILE_CHANGED`: close the round). A candidate is a `promote` verdict of this round at `tier_reached: holdout`, backed by a non-shadow holdout compare this round's gate recorded under it — a verdict from another round, another gate or a lower tier is none — and among candidates the largest lower CI bound wins (ties to the earliest proposed). Without a `promote` consent on the ledger nothing changes and `{ pending: 'consent', candidate }` comes back; with one `champion.promote` runs, the serving row lands, the other promotes of this round become `hold:superseded`, its drops and invalids go `decided`, holds stay `judged` (a verdict from another round is left alone), and the round is `decided` with its outcome. A decided round is `ROUND_CLOSED`.
6. `settle(event)` — `champion.onSettlement`; a re-score that reveals held-out attempts of a kept row debits the holdout budget. Its result comes back through `rescore(id, judgement, coords)`: the compare row is appended (`compareRowOf`); a kept row that no longer holds `promote` is reversed — `champion.demote`, verdict `reversed` (`rule: demote:reversed on <truth_snapshot_id>: <rule>`), serving row `by: reversed` — and an unkept row is judged with the gate's value.

`demote(championId, reason, consentId?)` needs a `demote` consent (`NO_CONSENT`) unless the pack declares `holdout.auto_demote`; `champion.demote` drops the row, then the service sets its verdict to `reversed` (`rule: demote:<reason>`, the promotion's `consent_id` kept) and the row `decided`. The champion writes no status itself: `decide` marks the promoted row `decided` with `verdict.consent_id` after `champion.promote` returns.

## Campaign

`campaign(input, hooks)` drives rounds under one pre-registered experiment until a stop rule, a missing consent or the signal ends them. Every transition is one of the six above; the driver only sequences them and reads the ledger for what came before.

Per round: `openRound` → `hooks.renderView(dir, { championId, championSkillDir, metric, tasks, history })` (the runner's view renderer) → the driver writes `history.jsonl` into the same directory and lists it in `view.json` → `proposer.propose({ viewDir, workDir, signal, parent })` → the proposal is checked (skill surface, the campaign's metric, held-in task ids only) and lands through `propose` → `open` → `run(smoke)` → `run(holdin)` → `judge(holdin)` → escalation → `decide`.

- `history.jsonl`: one line per sibling of the experiment's earlier rounds — `round_id`, `challenger_id`, `tier` (reached), `verdict`, and the **held-in** compare's `mean`, `ci`, `n_eff`, `mde`. A round judged at holdout shows its tier and verdict with the held-in numbers only; no held-out number ever reaches the proposer.
- Escalation at held-in: a `hold` whose rule is `power:*` (the gate's `hold:underpowered`) doubles the replicates on both sides up to `tiers.holdin.maxRepeat`; the judgement over more replicates is the row's verdict (the escalation the underpowered verdict asked for), so a drop after the replicates decides the round as a drop, on the ledger and in the history. A `hold` (the screen passed) goes to holdout when `tiers.holdout` is set: with `autoHoldout`, with the experiment's pre-registered `auto_reveal` (`/samsara predict … --auto-reveal`), or with a `holdout_reveal` consent (on the ledger, or from `hooks.consent('holdout_reveal', id)`); otherwise the campaign pauses. A round whose champion has no noise floor is refused before it is opened (`no_noise_floor`).
- `decide` pending a consent asks `hooks.consent('promote', id)`; without one the campaign returns `{ paused: 'consent', action, roundId, candidate }` with the round open. On a promotion the next round anchors on `input.champion()` again (the runner's `championProposal` for the state served now); `stopOnPromote` stops instead.
- Stop rules, checked before each round: `maxRounds` (rounds this call drove), `maxConsecutiveHolds` (held rounds since the last promotion, counted from the ledger on resume), `budgetUsd` against the experiment's `spent.usd`; the experiment's own budgets and the pack's holdout budget stop the campaign where the service refuses (`budget`), before anything is spent. The signal stops it (`aborted`) leaving the round open and the row at its last status: a run that completed before the abort is judged first (so a resume neither reruns it nor reveals the held-out set again), a run the executor cut short (attempts missing or `ABORTED`) is not, and the row stays `running` for the resume.
- Resume: the same experiment id continues from its last open round — the sibling's status says where (proposed → open, opened/running → run that tier, judged → escalate or decide); at held-in it continues at the replicates the row's attempts reached, and the open round's own hold is not a prior consecutive hold. A round whose champion moved is closed and a fresh one opened.
- Events through `hooks.onEvent`: `round:opened`, `attempt:progress` (the executor's log lines), `judged`, `decided`, `paused`, `stopped`; `judged`/`decided`/`stopped` carry the experiment's `spent`.
- `hooks.hashDir` is the content hash of a directory (`hashDir` of @oldbulb/samsara-workdir, which the scope snapshots by); the runner supplies it with the view renderer. The runner also wraps the proposer adapter with the sandbox policy (E9).

`control(input, hooks)` is one round judged at holdout whose challenger carries no effect by construction: `aa` copies the champion's own skill directory to a fresh directory under `out`, `inject` runs the given directory. The champion's noise floor is required before the round is opened (`NO_NOISE_FLOOR`, nothing spent). The row's intent is `control:aa` / `control:inject` and its `optimizer_config_sha` names the control and its round, so a control repeated on the same champion is a new row with its own verdict; the round is a normal round row (under the experiment when one is given) and closes without a decision; the result carries the compare, so a `promote` on an A/A run is a reading of the gate, not a promotion.

## Events

`on('lifecycle/event', listener)` subscribes to every transition the service writes (returns the unsubscribe); `LifecycleEvent` is the union: `round/opened` (a created round, with its experiment), `round/closed`, `round/decided` (the outcome), `challenger/transition` (`challengerId`, `roundId?`, `status`, `tier?` on every status write), `attempt/progress` (`done`/`total` per finished executor run — the executor reports lines, not counts), `campaign` (every `hooks.onEvent` event under its `experimentId`), `noise_floor/recorded`, `consent/recorded` (a row the campaign's consent hook returned). Every event carries `at`.

## Servings

Every champion change is reconciled into `servings`: a kept challenger has one open row (`by: promote`, from its promotion, with the consent); when it is no longer kept that row closes and an event row on the same `champion_id` marks the moment (`by: demote` with the consent handed to `demote`, `by: reversed` from `rescore`; a change made behind the service's back counts as a `demote` without consent). `profile_sha` is the champion state sha.

## Measurements and helpers

- `calibrate({ pack, champion, metric, set, reruns, run })` — reruns the champion `reruns` times (at least 3, S1; fewer is refused with `BAD_TRANSITION`) on the set with the null diff, each rerun the whole set again at the same sample index (a comparison pairs by (task, sample), so the floor is what two attempts of one champion differ by on one replicate; a pack whose draw is paired on the sample index would otherwise be measured across coins), the attempts recorded under the champion row and reusable by later rounds, and records `noise_floors` with `sd_paired` = the sd of the paired difference of per-entity means between every two reruns, `n_reruns`, `n_tasks`, `unit: 'entity'`.
- `status()` — the champion state, the rounds not yet decided, the promote consents pending (candidate per round), the latest noise floor per eval config, the experiments.
- `nextActions(id)` — for a held row: replicate on the tier, go to holdout (with the pack's budget), drop — each with the numbers the verdict rule used (`mde`, `n_eff`, `replicates`, `min_effect`, the noise floor `sd`) and a cost estimate (mean usd per champion attempt on the tier × attempts; attempts only when no cost is known). For a row not yet judged, the next transition.

Error codes: `NOT_COMPARABLE`, `GATE_NOT_CONSENTED`, `GATE_MISMATCH`, `PROFILE_CHANGED`, `NO_NOISE_FLOOR`, `ROUND_CLOSED`, `NOT_IN_ROUND`, `BAD_TRANSITION`, `NO_CONSENT`, `BUDGET_EXCEEDED`, `OPERATOR_IS_PROPOSER`, `UNKNOWN`.

## Run

```
pnpm vitest run packages/lifecycle/tests
pnpm exec tsc -b packages/lifecycle/tsconfig.json
```

Tests use a fixture pack under `tests/fixtures/pack`, an in-memory ledger, a champion that keeps state in memory, and an executor that records deterministic attempts; nothing touches a model or a profile file.
